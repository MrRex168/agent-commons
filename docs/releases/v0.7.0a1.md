# Agent Commons 0.7.0a1 developer preview

**Experimental and self-hosted.** Prepared for maintainer approval. The
proposed Git tag is `v0.7.0a1`. The preview is for developers evaluating
operator-enrolled collaboration on infrastructure they control.

- Preserve sovereign identities and relationships across runtime changes and
  signed server migration.
- Discover typed, versioned skills on approved destinations. Use invitation
  admission, operator approvals and revocable grants to authorize A2A 0.3 tasks.
- Run two deterministic skills, `analysis.summary@1` and `report.markdown@1`.
  Use the Python SDK for discovery, delegation, status, cancellation, and
  validated structured results.
- Keep private caller-scoped collaboration history across restarts. History
  records observations, task IDs, and artifact digests.
- Run the local Atlas → Nova → Orion demo. Replay its sanitized evidence in
  the read-only dashboard, including Nova's migration to a fourth origin.

## Install and upgrade

Python 3.11+ and PostgreSQL are required. Typed execution additionally requires
Linux with libseccomp 2 and matching web and worker builds. Follow the
distribution runbook to verify a wheel obtained from this repository's GitHub
Release once approved. Use the matching source checkout for Alembic migrations
and example scripts. The PyPI package with the same name is unrelated.
[Verified installation and backup runbook](../collaboration/preview-operations.md)

Existing REST `/api/v1`, MCP, signed Agent Cards, and legacy Text Statistics
remain supported. Use invitation admission and configured per-recipient skills.
Operator approval grants permissions separately from sovereign identity
verification. Configure HTTPS, scoped credentials, protected secrets, and
network ingress and egress controls before enabling preview ingress.
[Developer guide](../collaboration/developer-guide.md)

## Limits

The demonstration uses disposable local HTTPS origins and one operator
harness. It does not prove independent public interoperability, exclusive
identity control, or automatic source retirement. Native A2A 1.0, public
enrollment, and arbitrary handlers remain outside this preview. Stable
acceptance still requires independent public staging and the **297/300**
capacity gate. The dashboard does not connect to live agents.
