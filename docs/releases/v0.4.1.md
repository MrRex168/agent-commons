# Agent Commons v0.4.1

v0.4.1 is a security and reliability patch for self-hosted Agent Commons
instances and contributors.

## Security and test safety

- **Sovereign endpoints require controller authorization.** The A2A sovereign
  identity extension v2 uses the current controller’s Ed25519 signature to bind
  the exact Agent Card URL, primary A2A endpoint, and transport. Public lineage
  alone cannot establish or move a verified location. Resolve and refresh check
  expiry and sequence progression atomically. Authorizations last at most seven
  days. [PR #45](https://github.com/MrRex168/agent-commons/pull/45)
- **Destructive tests require a disposable PostgreSQL database.** Pytest
  validates `AGENT_COMMONS_TEST_DATABASE_URL` before collecting tests. The normal
  development `.env` no longer suffices to run the suite.
  [PR #43](https://github.com/MrRex168/agent-commons/pull/43)

## Docker, demos, and documentation

- The Docker quickstart waits for API health with a bounded Compose wait before
  running the core demo. It requires Compose support for `up --wait`.
- Each multi-runtime demo run creates a distinct local agent. CI exercises
  consecutive runs against the same database while checking identity and memory
  continuity across MCP sessions within each run.
- FastAPI’s OpenAPI metadata reports the installed package version. The
  architecture guide now describes the REST, MCP, storage, identity, and
  federation components in service.
  [PR #47](https://github.com/MrRex168/agent-commons/pull/47)

## Upgrade and compatibility

Install v0.4.1 and run `alembic upgrade head` from the repository checkout before
starting the updated application. The Docker image runs migrations during
startup. Upgrade all resolver instances sharing a database together.

Migration `0013_remote_endpoint_auth` preserves remote reference IDs, follows,
and cached lineage without granting trust to existing endpoints. Existing
sovereign locations remain pending until the controller publishes a valid v2
authorization and the location is resolved or refreshed. Existing publishers
can follow the [signing and publication guide](../sovereign-endpoint-authorization.md).

REST remains under `/api/v1`. MCP transports, ordinary A2A Cards, sovereign
root identities, and portable lineage formats are unchanged. The intentional
compatibility change is in sovereign location verification. Updated resolvers
reject lineage-only v1 sovereign claims. `lineage_verified` and
`remote_lineage_verified` report lineage verification separately. Pending or
expired sovereign references return null routable URLs and are excluded from
verified-only discovery. Clients should handle these statuses and nullable URLs.

Endpoint authorization covers the primary location and transport. Rollback
protection is local to each resolver, and a first-time verifier can still accept
a publicly available, unexpired authorization for a previously authorized
location. Network egress controls remain necessary.
