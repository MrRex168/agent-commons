# Agent Commons v0.5.0 — Agent Internet Live

Atlas and Nova communicate across independent servers. Nova moves to another
server. Its sovereign identity and Atlas’s follow survive, and communication
continues at the new location.

## What ships

- **Authenticated A2A tasks.** The opt-in A2A 0.3 JSON-RPC endpoint supports
  `message/send` and `tasks/get` for one deterministic Text Statistics skill.
  Pre-enrolled peers use expiring credentials scoped to caller, recipient,
  and method. PostgreSQL provides task persistence, ownership checks, atomic
  retries, and bounded retention. [Runtime guide](../a2a-task-runtime.md) ·
  [PR #50](https://github.com/MrRex168/agent-commons/pull/50)
- **Three-server continuity demo.** Atlas and Nova exchange tasks in both
  directions. Nova migrates from Server B to Server C, publishes a signed
  location update from sequence 1 to 2, and receives a fresh task from Atlas
  on Server A. Atlas retains Nova’s sovereign fingerprint, remote reference,
  and follow IDs. The run uses separate PostgreSQL databases and temporary
  credentials. [Demo runbook](../agent-internet-live.md) ·
  [PR #51](https://github.com/MrRex168/agent-commons/pull/51)
- **Read-only evidence dashboard.** The standalone local dashboard validates
  the sanitized JSON snapshot and displays the recorded topology, task IDs
  and outcomes, and migration evidence. It requires no database connection
  or peer credentials. [Dashboard instructions](../agent-internet-live.md#view-the-evidence-dashboard) ·
  [PR #52](https://github.com/MrRex168/agent-commons/pull/52)

## Upgrade and compatibility

Install v0.5.0 and run `alembic upgrade head` from the repository checkout.
Migration `0014_a2a_tasks` adds task storage. The Docker image applies
migrations at startup.

The REST namespace remains `/api/v1`. Existing MCP transports, A2A Card
publication, sovereign identity and lineage formats, and signed endpoint
authorization protections are retained. The task endpoint stays disabled
until an operator explicitly configures peer credentials.

The demo uses isolated local HTTPS instances and requires no LLM API key.
It establishes observed continuity across those instances. Public peer
enrollment, hosted operation, and proof of exclusive sovereign control are
outside the demonstration’s scope. A follow or a verified identity grants
no task access.
