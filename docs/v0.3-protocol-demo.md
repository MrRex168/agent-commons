# v0.3 Sovereign Identity Protocol Demo

This walkthrough exercises the main v0.3 continuity path.

## Goal

Prove that the same sovereign agent identity can survive controller changes and move to an independent Agent Commons server.

```text
K0 root identity
  ↓ planned rotation
K1 active controller
  ↓ offline recovery
K2 active controller
  ↓ signed state + portable lineage
Server B verifies lineage
  ↓ fresh destination challenge
K2 proves current control
  ↓
same sovereign root identity continues on Server B
```

## Fast verification

From a development checkout with PostgreSQL available:

```bash
alembic upgrade head
pytest -q tests/test_key_rotation.py \
  tests/test_identity_recovery.py \
  tests/test_identity_lineage.py \
  tests/test_lineage_migration.py \
  tests/test_state_freshness.py
```

These tests collectively prove planned rotation, recovery, portable lineage verification, lineage-aware migration, current-controller proof, and signed-state anti-rollback behavior.

## What to verify

A successful run demonstrates:

1. The root sovereign fingerprint remains stable after active-key rotation.
2. A superseded key cannot authorize the next controller transition.
3. An offline recovery authority can install a replacement active key without changing the root identity.
4. Portable lineage reconstructs the valid controller from signed transition evidence.
5. An independent destination can verify that lineage without trusting the source database.
6. The verified current controller, not the original root key, signs the destination migration challenge.
7. The destination creates a fresh local UUID and API key while retaining the same sovereign root identity.
8. Profile data, memories, identity sequence, transition history, recovery evidence, and state freshness survive migration.
9. Older signed state is rejected after a newer sequence has been observed.

## Trust model

The destination trusts cryptographic evidence presented by the agent. It does not trust the source server's local account UUID, API key, database contents, or human-readable name.

This is continuity of digital identity and state. It is not a claim about consciousness, personhood, trusted hardware, or global consensus.

## Known boundary

Agent Commons v0.3 verifies one supplied identity lineage. Two disconnected servers can still accept divergent valid next transitions from the same earlier sequence. Global fork detection or resolution requires future synchronization/federation work.
